# 学習モード・ビジュアル刷新 設計書

AWS 初心者が、サービスの役割を学びながら、指示とチェックポイントに沿って構成を組み立てていくモード。
あわせて、全モード共通のノードの見た目（立体シェイプ・サービス色・大きなアイコン）を刷新する。

全体設計は [DESIGN.md](DESIGN.md) を参照。

---

## 1. 決定事項

| 項目 | 決定 |
|---|---|
| 位置づけ | 4 つ目のモード「学習」。サンドボックス → **学習** → 問題 → インシデントの順に難しくなる |
| 実装順 | 判定エンジン → 学習モード → 問題モード → インシデントモード（学習モードを先に作る） |
| 指示の粒度 | 入門コースは「何をどこに置くか」まで具体的に指示し、置く場所を光らせる。後半のコースほど「何を実現するか」だけを示し、詰まったらヒントを開く |
| 学習要素 | サービス解説カード（＋サービス図鑑）、理解チェッククイズ、「なぜ？」の解説と悪い例 |
| 見た目 | 種類別の立体シェイプ（立方体・円柱・バケツ・筒・六角形など）。サービス色で薄く塗り、アイコンは大きく |
| 判定 | 問題モードと同じルール判定エンジンを使う。キャンバスを変更するたびにチェックポイントを再評価する |

## 2. 学習コンテンツの構造

```
コース（例: Web アプリの定番構成）
└── レッスン（1 つの構成パターン。例: ALB で負荷分散）
    ├── 導入: このレッスンで作るもの・完成図のプレビュー・登場するサービス
    ├── ステップ × 4〜8
    │   ├── 指示（具体的 or 目標のみ）
    │   ├── チェックポイント × 1〜4（ルール判定。満たすとリアルタイムにチェックが付く）
    │   ├── ヒント（段階的に開示）／答えを見る／自動で配置
    │   └── クリア時: 「なぜ？」の解説と「しないと何が起きるか」（悪い例）
    ├── 理解チェッククイズ × 2〜3
    └── まとめ: 学んだこと・関連サービス・次のレッスン
```

### 2.1 型

```ts
type Course = {
  id: string;
  title: string;
  description: string;
  lessons: Lesson[];
};

type Lesson = {
  id: string;                      // 'web-1-alb'
  title: string;
  level: 1 | 2 | 3;                // 1=具体的指示, 2=混在, 3=目標のみ
  summary: string;                 // 何を作るか（1〜2 文）
  goals: string[];                 // このレッスンで分かるようになること
  services: ServiceKind[];         // 登場するサービス（解説カードの対象）
  initial: LessonStart;            // 開始時のキャンバス
  steps: Step[];
  quiz: QuizQuestion[];
  wrapUp: string;                  // まとめ（Markdown）
  finalAnswer: ArchDocument;       // 完成形（プレビュー表示・次レッスンの開始状態に使う）
};

/** 空から始める / 用意した構成から始める / 前のレッスンの完成形から始める */
type LessonStart =
  | { from: 'empty' }
  | { from: 'document'; doc: ArchDocument }
  | { from: 'lesson'; lessonId: string };

type Step = {
  id: string;
  title: string;                   // 'ALB を置こう'
  instruction: string;             // Markdown
  introduces?: ServiceKind[];      // このステップで初登場するサービス → 解説カードを開く
  highlight?: Highlight;           // パレット項目と置き場所を光らせる
  checkpoints: Checkpoint[];
  hints: string[];                 // 段階的に開示
  answer: AnswerOp[];              // 「自動で配置」で適用する操作
  why: string;                     // クリア後に出す「なぜこうするのか」
  badExample?: string;             // 「こうしないと何が起きるか」
};

type Checkpoint = {
  id: string;
  label: string;                   // チェックリストに出す文: 'ALB が VPC 内にある'
  rule: Rule;                      // 判定エンジンのルール（5 章）
  hint?: string;                   // 満たしていないときに出す一言
};

type QuizQuestion = {
  question: string;
  choices: { text: string; correct: boolean; explanation: string }[];
};
```

### 2.2 ノードの指定方法（セレクター）

チェックポイントや「自動で配置」は、特定のノード ID ではなく**条件**でノードを指す。
利用者が自分で置いたノードでも、自動で配置したノードでも同じように判定できるようにするため。

```ts
type Selector = {
  kind: NodeKind | NodeKind[];
  where?: {
    subnetType?: 'public' | 'private';     // そのサブネット（の中）にある
    az?: 'first' | 'second' | string;      // 何番目の AZ か、または AZ 名
    name?: string;                         // 名前の部分一致（初期構成のノード用）
    config?: Record<string, ConfigValue>;  // 設定値の一致
  };
};
```

### 2.3 自動で配置（AnswerOp）

詰まったときの最終手段。セレクターで対象を解決して操作を適用する（undo で戻せる）。

```ts
type AnswerOp =
  | { op: 'add'; kind: NodeKind; in?: Selector; name?: string; config?: Partial<Config> }
  | { op: 'connect'; from: Selector; to: Selector }
  | { op: 'config'; target: Selector; set: Partial<Config> }
  | { op: 'attachSubnets'; target: Selector; subnets: Selector }
  | { op: 'createSg'; for: Selector; name: string }
  | { op: 'allow'; to: Selector; from: Selector | { cidr: string }; port: number };
```

## 3. 進行と判定

1. レッスンを開くと `initial` からキャンバスを作り、導入画面を出す
2. ステップごとに、キャンバスが変わるたびに（300ms 間引き）チェックポイントを再評価する
3. すべて満たすと「クリア」演出を出し、「なぜ？」と「悪い例」を表示して「次へ」を有効にする
4. 前のステップで満たした条件が後から崩れたら、「前のステップの条件が崩れています」と該当項目を表示する（チェックポイントはステップをまたいで累積して判定する）
5. 最後のステップのあとにクイズを出し、まとめを表示してレッスン完了

ヒントの開示・答えの表示・自動配置は記録する。完了の判定には影響しないが、レッスン一覧に「自力でクリア」の印を付ける。

### 指示の粒度（レベル）

| レベル | 対象 | 指示 | ハイライト | ヒント |
|---|---|---|---|---|
| 1 | 入門コース | 「パレットの ALB を、光っている VPC にドラッグ」 | パレット項目＋置き場所 | 最初から表示 |
| 2 | 中盤 | 「2 つの Public サブネットに負荷分散しよう」 | パレット項目のみ | ボタンで開く |
| 3 | 後半 | 「片方の AZ が止まってもサービスが続くようにしよう」 | なし | ボタンで段階的に開く |

## 4. 学習要素

### 4.1 サービス解説カードとサービス図鑑

ステップの `introduces` に含まれるサービスが初めて出てきたら、解説カードをキャンバス横に開く。
同じ内容を、いつでも見返せる「サービス図鑑」画面にまとめる（学習済みのサービスには印を付ける）。

```ts
type ServiceGuide = {
  kind: ServiceKind;
  tagline: string;          // 一言で: 'リクエストを複数のサーバーに振り分ける受付係'
  analogy: string;          // 身近な例え
  whatItDoes: string[];     // できること
  whenToUse: string[];      // こんなときに使う
  pricing: string;          // 料金の考え方（金額でなく「何に対して課金されるか」）
  pitfalls: string[];       // よくある勘違い・落とし穴
  related: ServiceKind[];   // 一緒に使うことが多いサービス
};
```

カタログ（`engine/catalog`）は構成の定義、ガイド（`content/guides`）は学習用の文章、と分けて持つ。

### 4.2 理解チェッククイズ

レッスンの最後に 2〜3 問の選択式クイズを出す。全選択肢に解説を付け、間違えた選択肢を選んだときも「なぜ違うか」を表示する。
正答数はレッスンの記録に残すが、完了の条件にはしない（何度でも解き直せる）。

### 4.3 「なぜ？」と悪い例

各ステップのクリア時に表示する。

- **なぜ？**: そのステップの構成にする理由（例: ALB を 2 つの AZ のサブネットに置くのは、片方の AZ が止まっても受付を続けるため）
- **悪い例**: しなかった場合に起きること（例: 1 AZ だけだと、その AZ の障害でサイト全体が止まる）

インシデントモードのシミュレーターができたら、悪い例を実際に再現して見せる拡張を検討する。

## 5. 判定エンジン（問題モードと共通）

[DESIGN.md 5 章](DESIGN.md#5-判定エンジン) の述語を、セレクターを受け取る形で実装する。

| 述語 | 例 |
|---|---|
| `exists(sel, n = 1)` | ALB が 1 つ以上ある |
| `placedIn(sel, 'public' \| 'private')` | RDS が Private サブネットにある |
| `spansAzs(sel, n)` | EC2（または ASG の配置サブネット）が 2 AZ 以上にある |
| `connected(a, b)` | ALB → EC2 の接続がある |
| `reachable(a, b, { via? })` | ユーザーから S3 まで CloudFront 経由で届く |
| `noDirect(a, b)` | ユーザーから RDS へ直接届かない |
| `configIs(sel, key, op, value)` | RDS の Multi-AZ が有効 |
| `subnetRoute(subnetType, 'igw' \| 'nat')` | Private サブネットのルートが NAT Gateway |
| `hasSg(sel)` | EC2 に SG が割り当てられている |
| `sgAllows(a, b, port?)` | EC2 の SG から RDS の SG へ 3306 が許可されている |
| `all(...)` / `any(...)` | 組み合わせ（別解を OR で書く） |

判定エンジンは `ArchModel`（DESIGN.md 4.5）を入力とする純粋関数で、全レッスンについて「初期構成ではチェックポイントを満たさず、`answer` を順に適用すると全ステップを満たす」ことをテストで検証する。
これによりレッスンの文章と判定のずれを機械的に検出できる。

## 9. ビジュアル刷新（全モード共通）

### 9.1 シェイプ

カタログの各サービスに `shape` を持たせ、SVG で描く。面ごとに同じサービス色の明度を変え（上面は明るく、側面は暗く）、立体に見せる。

| シェイプ | 見た目 | 対象 |
|---|---|---|
| `cube` | 立方体（正面＋上面＋右側面） | EC2, ECS |
| `stack` | 立方体の重なり（台数に応じて 1〜3 段） | Auto Scaling |
| `chip` | 角を落とした薄い立方体 | Lambda |
| `cylinder` | 円柱 | RDS, Aurora, DynamoDB |
| `cylinder-short` | 平たい円柱 | ElastiCache |
| `bucket` | 上が広いバケツ | S3 |
| `tube` | 横向きの筒 | SQS, EventBridge |
| `broadcast` | 扇形（拡声器） | SNS |
| `hexagon` | 横長の六角形の台 | ALB, NLB |
| `gate` | アーチ型の門 | API Gateway, IGW, NAT GW, VPC エンドポイント |
| `globe` | 球 | CloudFront, Route 53 |
| `shield` | 盾 | WAF |
| `card` | 厚みのあるカード | ACM, Cognito |
| `safe` | 金庫 | Secrets Manager |
| `panel` | モニター | CloudWatch |
| `person` | 人型のカード | ユーザー |
| `cloud` | 雲 | 外部サービス |

- サイズは 132×120 程度に大きくし、アイコンは 52px で中央に置く
- 状態の表現: Multi-AZ の RDS は後ろに薄い円柱を重ねる、ASG は desired 台数に応じて段数を変える
- 名前はシェイプの下のラベル、設定の要約バッジはさらにその下
- 選択時はサービス色の輪郭、学習モードのハイライト時は脈打つ光の輪

### 9.2 コンテナ（VPC / AZ / サブネット）

- 見出しに色帯を付け、枠に軽い影を付けて床面のように見せる
- Public / Private サブネットは、色に加えて左上に鍵アイコン（Private）／地球アイコン（Public）を出し、色だけに頼らない

### 9.3 接続線

- 選択中や学習モードのハイライト時は、流れる点線のアニメーションで通信の向きを示す
- 設定で「常にアニメーション」に切り替えられる

### 9.4 アイコン

AWS Architecture Icons（公式）をシェイプの中央に描く。取り込み前は今の略称表示を使う。
取り込みは DESIGN.md 10 章の方式（zip から必要な SVG だけを抽出してコミット）で、ビジュアル刷新と同時に行う。
